## 1. 概要: Impression-Farmer-Finderとは？
企業・クリエーターのSNS運用において、X（旧Twitter）の返信欄に流入するスパムアカウント、いわゆる「インプレゾンビ」を可視化するPythonツールです。

X APIで取得したリプライと投稿者情報をもとに、Pythonによるルールベース判定とGPT APIによる文脈判定を組み合わせ、スパム疑いの返信を「晴れ・曇り・雨」の三段階で分類します。

本ツールは、SNS運用担当者が大量の返信を人力で確認する負担を軽減し、健全なユーザー反応の分析やコミュニティ管理を支援することを目的としています。

## 2. 開発背景
現代において、企業やクリエーターがSNS運用を行う場合、エンゲージメントを最大化することで、テレビ・新聞・ラジオなどの既存メディアと比較して、高い費用対効果で知名度向上やブランドイメージ向上を図ることが可能です。

しかし近年、
X（旧Twitter）では、
インプレッション収益化を目的とした
スパムアカウント
（いわゆる「インプレゾンビ」）の大量流入が問題となっています。

これらのアカウントは、

* 投稿内容と無関係な返信
* 意味を成していない短文投稿
* 他ユーザー投稿のコピー＆ペースト
* 同一パターンの大量投稿

などを行い、
本来SNSで想定されている

* ユーザー同士のコミュニケーション
* コミュニティ形成
* 健全な反応分析

といった機能を阻害しています。

また、
企業SNSが莫大なエンゲージメント
（いわゆる「バズ」）を獲得していても、
実際には返信欄の大部分がスパムアカウントによって占有されているケースも存在しており、
エンゲージメント効率の観点から大きな機会損失が発生しています。

さらに、
大量の返信を人力で確認し、
スパム判定やブロック対応を行う場合、
SNS運用担当者には多大な時間的コストが発生します。

加えて、
誤って健全なユーザーをブロックした場合には、
ブランドイメージ低下やコンプライアンス問題
（いわゆる「炎上」）につながる危険性も存在します。

そこで本プロジェクト
「Impression-Farmer-Finder（IFF）」では、
X APIおよびChatGPT APIを利用し、
スパムアカウントをスコアリング形式で可視化することで、
SNS運用時の分析・判定作業の省力化を目的として開発しました。

## 3. 実際の分析例
以下は、企業SNSアカウントが莫大なエンゲージメント
（いわゆる「バズ」）を獲得した実際の例です。

![バズ投稿の例](images/buzz_post_blurred.png)

* 返信：約307件
* リポスト：約1万件
* いいね：約6.1万件
* ブックマーク：約4,500件

エンゲージメント数のみに注目した場合、
理想的な広告活動・SNSマーケティング成功例に見えます。

しかし本ツールによる分析では、
返信307件のうち約240件、
全体の約80%がスパムアカウント
（いわゆる「インプレゾンビ」）による反応で構成されていることを確認しました。

このように、
表面的なエンゲージメント数のみでは、
実際の広告効果やユーザー反応を正確に把握できないケースが存在します。

## 4. スパムアカウントの実例
以下は、実際に確認されたスパム返信の例です。

![スパム返信例1](images/spam_reply_01.png)

![スパム返信例2](images/spam_reply_02.png)

スパムアカウントの内訳としては、
以下のような特徴が確認されました。

* 日本語を使用しているものの、企業アカウントの投稿内容・分野と一切関連性のない返信
* 単語のみ、あるいは意味を成していない短文投稿
* 他ユーザーの投稿内容をコピー＆ペーストしただけの返信
* 同一パターンを繰り返す大量投稿

返信欄にスパム投稿が大量流入することで、
本来SNSで想定されているユーザー同士のコミュニケーション、
ファンコミュニティ形成、
投稿内容に対する健全な反応が阻害されているのが現状です。

その結果、
企業SNSが莫大なエンゲージメントを獲得していても、
実際にはエンゲージメント効率において
大きな機会損失が発生していると考えられます。

## 6. 主な機能
- X APIによるリプライ取得
- pagination_token による複数ページ取得
- tweet_id による重複排除
- tweet/user ペア化
- Pythonルールベースによる一次判定
- 晴れ / 曇り / 雨 の三段階分類
- GPT APIによる境界例の二次判定
- 判定結果のtxt保存

## 7. システム構成・判定フロー
本ツールでは、
全件をGPT APIへ送信するのではなく、
まずPythonによるルールベース判定で一次分類を行います。

Python側で明確に判定できる返信についてはそのまま分類し、
判定が難しい境界例のみをGPT APIによる二次判定へ回す構成としています。

これにより、

* API利用コスト削減
* 判定速度向上
* 文脈判断への対応

を両立しています。

==判定フロー==
```text
X API
  ↓
リプライ・投稿者情報取得
  ↓
tweet_id による重複排除
  ↓
Pythonルールベース一次判定
  ↓
境界例のみGPT API二次判定
  ↓
「晴れ / 曇り / 雨」に分類
  ↓
txt形式で結果保存
```

## 9. 使用技術
本ツールでは、以下の技術・ライブラリ・APIを使用しています。

==使用言語==
- Python

==使用API==
- X API
  - 対象投稿に対するリプライ取得
  - `conversation_id` を用いた返信検索
  - `pagination_token` による複数ページ取得
  - tweet情報・user情報・public_metrics の取得

- OpenAI API
  - Python一次判定で判断が難しい投稿に対するGPT二次判定
  - 投稿本文、投稿者情報、公開メトリクス、Python判定理由をもとにした文脈判定

==使用ライブラリ＝＝
- requests
  - X APIへのHTTPリクエスト送信に使用

- openai
  - GPT APIによる二次判定に使用

- os
  - 環境変数やファイルパスの扱いに使用

- datetime
  - 判定結果txtのタイムスタンプ付き保存に使用
